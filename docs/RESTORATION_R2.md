# Восстановление R2 — сохранность прогресса и резервных копий

05.11.2026. Внутренняя проверочная сборка, не финальный выпуск.
Основные дефекты аудита D05, D06, D07 исправлены в описанном и проверенном объёме.

## Изменения

`src/storage.js` хранит один авторитетный снимок `mi-espanol-recovery-state-v3`:
progress + settings + settingsMeta + conflicts. Старые ключи progress/theme/recovery11-settings
читаются при миграции, но не переписываются. Изменённые записи получают updatedAt.
Повреждённый новый снимок не заменяется старой копией или пустым профилем: запись блокируется,
исходные строки доступны отдельным экспортом. При недоступном хранилище нет ложного успеха.

`src/backup.js` экспортирует v3 с SHA-256 и импортирует v1/v2/v3. Проверяются известные
структуры, типы записей, неделя, интервалы, даты, счётчики, глубина и опасные имена полей.
Для старого v1 контрольной суммы не было: UI прямо сообщает, что проверена только структура.
Для v2 сохраняется совместимость с исходной FNV1a32; v3 использует Web Crypto SHA-256.
Неизвестный формат и повреждённая сумма не меняют текущий снимок.

Проверенный файл сначала проходит анализ и объединение, затем UI показывает состав и
запрашивает подтверждение импорта. При совпадении записей используются updatedAt/last/at/lastAt,
а не due (будущий срок повторения не является временем совершения действия). Более поздний
неуспех может заменить прежний успех — это реальное новое событие. Старый файл не откатывает
более свежую запись. Если порядок определить нельзя, текущее значение сохраняется, другое
попадает в конфликтный архив. Повторный импорт не создаёт копии тех же конфликтов.

Неизвестные поля прогресса, снимка и настроек сохраняются или попадают в журнал конфликта.
Новая настройка не стирает неизвестные поля прежней записи. Тема и доступность восстанавливаются
по их метаданным свежести; v1/v2 без настроек не сбрасывают текущие настройки.

Фиксация использует одну запись localStorage, чтение-подтверждение и попытку отката при ошибке.
Состояние интерфейса обновляется только после успешной записи. Это проверено для текущего
браузера и модели отказа записи; межвкладочная конкурентная запись и все режимы iOS не принимались.
Журнал конфликтов сохраняется в экспортируемой копии; отдельный UI выбора победителя пока не создан.

## Ограничения и следующий шаг

Проверки используют синтетические данные; реальные прежние пользовательские backup-файлы
не получены. Safari/iPhone, долгое хранение и file:// ещё не приняты. Для SHA-256 необходима
поддержка Web Crypto в выбранном режиме браузера; отсутствие API вызывает понятную ошибку,
а не отключение проверки суммы. Модель курса, единый журнал всех учебных событий и прочие
требования ТЗ не объявляются реализованными этим пакетом.

Далее R3: связи недель и первоисточников, ID и предметная вычитка; затем недостающий курс A1–B2.
