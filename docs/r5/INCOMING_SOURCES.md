## Передача

Если файлы сохранились: в отдельной ветке incoming-sources поместить каждый неизменённый HTML в incoming/raw/ и сделать коммит. Размеры, указанные прежним manifest: около 38,9 МБ, 12,2 МБ и 12,1 МБ; они ниже ограничения GitHub 100 МБ на один Git-файл. Проверять реальный размер перед отправкой; если больше лимита, использовать Git LFS/Release. Не заменять R3/R4/R5 и не открывать полученный HTML в рабочем приложении до статического анализа. Ветка должна быть основана на сохранённом коммите, не заменять историю main.

Вариант без Git: каждый небольшой HTML загрузить отдельно; большой архив/HTML разбить на части по 20 МиБ существующим tools/transfer_parts.py split SOURCE NEW_DIRECTORY. Передать parts.json и все part-*.bin; команда join проверяет каждый хэш и общий SHA-256, не перезаписывает существующий выходной файл. Части — двоичное разбиение, не самостоятельные ZIP. Если материалов нет, этот путь остаётся подготовленным, а не блокирует создание новых уроков.

## Приёмка и аудит

1. Прочитать предоставленный коммит/части в отдельном каталоге. Записать источник передачи, имя, размер, полный SHA-256 и исходный Git-коммит. Сохранить байты без правок; заголовок/имя файла не доказывает его происхождение.
2. Для каждого файла запустить python tools/intake_html.py incoming/raw/ИМЯ.html --report audit/incoming/УНИКАЛЬНОЕ_ИМЯ.json. Инструмент только читает файл и разбирает JSON-литерал DB; JavaScript и внешние ссылки не выполняются. Отчёт не перезаписывается. Несовпадение ожидаемого SHA отмечается, файл не выдается за ожидаемую сборку.
3. Проверить все блоки данных и скриптов статически. Если DB не разобран, это статус «нужен ручной разбор», а не отсутствие материалов. Встроенные массивы вне DB и тексты в разметке требуют отдельной проверки. Не использовать eval или исполнение неизвестного кода для извлечения.
4. Сопоставить каждую сущность по исходному ID/позиции, нормализованному содержимому и полному хэшу. Точное совпадение, иное значение того же заголовка, языковая правка и действительно новый материал — разные случаи. Автоматические хэши верхних массивов не заменяют ручную проверку таблиц, уроков и близких дублей.
5. Новые материалы сначала в отдельный реестр с SHA файла и точным указателем. Отдельно — редакторские исправления и новые авторские примеры. Материалы R5 с origin NEWLY_AUTHORED_R5_NOT_RECOVERED не менять на «исторические», даже если позднее найден похожий текст.
6. Интегрировать после языковой проверки, без перенумерации старых записей. Запустить тесты сохранения прогресса, резервных копий, маршрутов, карточек и TTS; сохранить воспроизводимый пакет и Git-коммит. Браузерное выполнение самого неизвестного исторического HTML для первого анализа не требуется.

Никаких новых источников или учебных единиц эта процедура сама по себе не добавляет. В R5 три файла по-прежнему не прочитаны.
