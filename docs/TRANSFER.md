# Как передать недостающие материалы

Примечание от 05.11.2026: пользователь сообщил, что других файлов у него нет. Эти способы передачи оставлены на случай последующего обнаружения копий и не являются требованием продолжения.

ALL_AVAILABLE_HTML ZIP не признан повреждённым или утраченным. Инструмент `download_file`
отказался принять файл из-за лимита **32 МиБ на один файл**. Его состав не был прочитан.

## Вариант 1: архивы по HTML

Распакуйте расширенный архив у себя и упакуйте каждый HTML отдельно в ZIP размером
меньше 30 МиБ. Передайте все части, включая документы/скрипты, если они отличаются от STARTER.
Присылайте и неизвестные кандидаты: не нужно заранее решать, какой «главный».
Три файла уже перечислены в исходном манифесте, но отсутствуют в STARTER:

- `Mi_Espanol_4_4_REBUILT_iPhone.html` — исходный размер 38 852 641 байт;
- `Mi_Espanol_Integrated_Review_2026-11-02.html` — 12 151 111 байт;
- `Mi_Espanol_Personal_Complete_Review.html` — 12 142 861 байт.

Первый HTML сам превышает лимит, поэтому нужен ZIP или разбиение, даже при отправке отдельно.
Переданные размеры и ожидаемые SHA — исторический манифест; фактические байты ещё не проверены.

## Вариант 2: побайтовое разбиение исходного ZIP

Включён `tools/transfer_parts.py`: он не распаковывает и не изменяет оригинал, создаёт
части по 20 МиБ и `parts.json` с хэшами частей и целого файла. На машине с Python 3:

```bash
python3 tools/transfer_parts.py split MI_ESPANOL_CODEX_ALL_AVAILABLE_HTML_2026-11-05.zip spanish-parts
```

Передайте **каждый** `part-0000.bin`, `part-0001.bin`, … и `parts.json` отдельными вложениями.
После получения файлы будут объединены в порядке манифеста:

```bash
python3 tools/transfer_parts.py join spanish-parts/parts.json restored-ALL_AVAILABLE_HTML.zip
```

Команда проверяет каждый SHA до записи и итоговую SHA после объединения; существующий
выходной файл не перезаписывает. Затем нужен безопасный разбор списка ZIP и распаковка
без перезаписи canonical STARTER. Сам по себе успешный join не доказывает полноту архива.

## Вариант 3: Git

Поместите файлы в отдельный каталог/ветку существующего репозитория `VvikB/Mi-Espa-ol`
и сообщите ветку/commit/path. Не заменяйте единственную старую копию и не переименовывайте
кандидатов в «final». Доступ к выбранному GitHub уже был проверен через штатный HTTPS-прокси;
токен в чате не нужен. После появления коммита выполняются read-only fetch/сверка и
сохранение полученных исходных байтов с отдельными хэшами.

Локальные коммиты текущего аудита не отправлялись на GitHub. Резервный Git bundle позволяет
перенести всю локальную историю; публикация в удалённый репозиторий не заявляется.
